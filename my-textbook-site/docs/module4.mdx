# Module 4: Vision-Language-Action (VLA)

Welcome to the capstone module: Vision-Language-Action (VLA). This is where all the previous modules converge. We will integrate Large Language Models (LLMs) with our humanoid robotics stack, enabling our robot to understand natural language commands and execute complex tasks autonomously in a simulated environment. This module focuses on the "cognitive" layer, where an LLM acts as the robot's brain, orchestrating perception, navigation, and manipulation.

## Section 1: The End-to-End VLA Pipeline

*(Based on Tasks T1.1, T1.2, T1.3)*

### A Cognitive Robotics System

Imagine speaking a command to your humanoid robot: "Robot, please bring me the red mug from the kitchen table." This module is about building the system that allows the robot to understand that command, plan a series of actions, and execute them in the physical world (or our digital twin). This is the essence of Vision-Language-Action.

The VLA pipeline is a sophisticated orchestration of several components, each playing a critical role in transforming a high-level natural language instruction into a series of robotic behaviors. It builds directly upon the ROS 2 communication (Module 1), physics-based simulation (Module 2), and AI perception/navigation (Module 3) foundations we've established.

### Architectural Diagram: The VLA Blueprint

*(Textual description of the architectural diagram)*

The VLA pipeline can be visualized as a series of connected blocks, with ROS 2 topics and actions serving as the communication channels:

1.  **Voice Input**: A microphone captures the user's spoken command.
2.  **Speech-to-Text (STT) Node**: This ROS 2 node processes the audio and converts it into a text string.
    -   *Output*: `/user_command` (ROS 2 `std_msgs/msg/String`)
3.  **LLM Planner Node**: This ROS 2 node receives the text command, interacts with a Large Language Model (LLM), and outputs a structured task plan.
    -   *Input*: `/user_command`
    -   *Output*: `/task_plan` (ROS 2 custom message, e.g., `vla_system/msg/TaskPlan`)
4.  **ROS 2 Orchestrator Node**: This is the central executive. It parses the `/task_plan`, translates each step into specific ROS 2 actions or service calls, and manages their sequential execution.
    -   *Input*: `/task_plan`
    -   *Outputs*: Calls to Nav2 Action Server (`/navigate_to_pose`), Isaac ROS perception services (e.g., `/detect_object`), and other manipulation services.
5.  **Perception & Action (Module 3)**:
    -   **Nav2 Stack**: Executes navigation commands from the Orchestrator, using maps and localization from VSLAM.
    -   **Isaac ROS Perception**: Provides object detection, pose estimation, or other visual information when requested.
    -   **Humanoid Control**: Low-level motor control for walking, grasping, etc. (abstracted for this module).
6.  **Simulation Environment (Module 2)**: Isaac Sim provides the virtual world for the robot to operate in, generating realistic sensor feedback.
7.  **ROS 2 Runtime (Module 1)**: The underlying middleware connecting all components.

## Section 2: From Voice to Text

*(Based on Tasks T2.1, T2.2, T2.3, T2.4)*

The first step in our pipeline is to accurately convert spoken language into text. We will use a simple Python script within a ROS 2 node to achieve this. For the speech-to-text functionality, we can leverage libraries like OpenAI's Whisper model (available via Hugging Face Transformers for local inference).

### `speech_to_text_node.py`

This Python script will set up a ROS 2 node that continuously listens for audio input, transcribes it, and publishes the text to a ROS 2 topic.

```python
# vla_system/vla_system/speech_to_text_node.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
import speech_recognition as sr
import threading
import time

class SpeechToTextNode(Node):
    def __init__(self):
        super().__init__(\'speech_to_text_node\'
        self.publisher_ = self.create_publisher(String, \'user_command\', 10)
        self.recognizer = sr.Recognizer()
        self.microphone = sr.Microphone()
        self.get_logger().info(\'Speech-to-Text Node started. Listening for commands...\'

        self.listening_thread = threading.Thread(target=self._listen_loop)
        self.listening_thread.daemon = True
        self.listening_thread.start()

    def _listen_loop(self):
        while rclpy.ok():
            try:
                with self.microphone as source:
                    self.recognizer.adjust_for_ambient_noise(source)
                    self.get_logger().info("Say something!")
                    audio = self.recognizer.listen(source, timeout=5, phrase_time_limit=10) # Adjust timeout as needed
                
                text = self.recognizer.recognize_google(audio) # Using Google Web Speech API for simplicity
                # For local Whisper:
                # from transformers import pipeline
                # pipe = pipeline("automatic-speech-recognition", model="openai/whisper-tiny.en")
                # text = pipe(audio.frame_data)["text"]

                self.get_logger().info(f"You said: '{text}'")
                msg = String()
                msg.data = text
                self.publisher_.publish(msg)
                time.sleep(1) # Small delay to prevent rapid processing

            except sr.WaitTimeoutError:
                self.get_logger().info("No speech detected. Listening again...")
                continue
            except sr.UnknownValueError:
                self.get_logger().warn("Could not understand audio")
            except sr.RequestError as e:
                self.get_logger().error(f"Could not request results from Google Speech Recognition service; {e}")
            except Exception as e:
                self.get_logger().error(f"An unexpected error occurred: {e}")
                time.sleep(1)


def main(args=None):
    rclpy.init(args=args)
    node = SpeechToTextNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## Section 3: The LLM as a Cognitive Planner

*(Based on Tasks T3.1, T3.2, T3.3, T3.4, T3.5)*

The LLM acts as the robot\'s high-level brain, translating abstract human commands into a structured, executable plan.

### Prompt Engineering for Robotics

The key is the "system prompt" or "context prompt." This tells the LLM:
-   **Who it is**: "You are a helpful robot assistant."
-   **What its capabilities are**: A list of available actions (functions) and their parameters.
-   **What its goal is**: To generate a structured JSON plan.

### System Prompt Example (Conceptual)

```yaml
# system_prompt.yaml
system_prompt: |
  You are an autonomous humanoid robot assistant.
  Your goal is to fulfill user commands by generating a sequence of actions.
  You have the following capabilities:

  - navigate_to(location: string): Navigates the robot to a specified location (e.g., \"kitchen\", \"living_room\").
  - find_object(object_name: string, color: string = \"any\"): Uses vision to find an object with a given name and optional color. Returns object_id (string).
  - pick_up(object_id: string): Grasps the specified object.
  - place_object(location: string = \"current_location\"): Places the held object at a specified location.

  Generate a JSON array of actions for the user\'s command. Respond ONLY with JSON.
  Example: User command: \"Go to the kitchen and find the red apple.\"
  Response:
  ```json
  [
    {"action": "navigate_to", "parameters": {"location": "kitchen"}},
    {"action": "find_object", "parameters": {"object_name": "apple", "color": "red"}}
  ]
  ```

user_command_prefix: "User command: "
```

### `llm_planner_node.py`

This node will subscribe to the `/user_command` topic, send the combined prompt to an LLM (e.g., through an API or a local server), and publish the resulting structured plan.

```python
# vla_system/vla_system/llm_planner_node.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
import json
import os
import requests # For API calls

# Define a custom message type for TaskPlan
# Create vla_system/msg/TaskPlan.msg:
# string plan_id
# string[] actions_json # Each element is a JSON string of an action

class LLMPlannerNode(Node):
    def __init__(self):
        super().__init__(\'llm_planner_node\')
        self.subscription = self.create_subscription(
            String,
            \'user_command\',
            self.command_callback,
            10)
        self.publisher_ = self.create_publisher(String, \'task_plan\', 10) # Publishing as String for simplicity
        # For actual TaskPlan custom message, need:
        # from vla_system.msg import TaskPlan
        # self.publisher_ = self.create_publisher(TaskPlan, 'task_plan', 10)

        self.system_prompt = self._load_system_prompt()
        self.llm_api_endpoint = os.getenv('LLM_API_ENDPOINT', 'http://localhost:8000/v1/chat/completions') # Example for local LLM
        self.get_logger().info(f"LLM Planner Node started. LLM Endpoint: {self.llm_api_endpoint}")

    def _load_system_prompt(self):
        # Load system prompt from a file or directly define
        return """
        You are an autonomous humanoid robot assistant.
        Your goal is to fulfill user commands by generating a sequence of actions.
        You have the following capabilities:

        - navigate_to(location: string): Navigates the robot to a specified location (e.g., \"kitchen\", \"living_room\").
        - find_object(object_name: string, color: string = \"any\"): Uses vision to find an object with a given name and optional color. Returns object_id (string).
        - pick_up(object_id: string): Grasps the specified object.
        - place_object(location: string = \"current_location\"): Places the held object at a specified location.

        Generate a JSON array of actions for the user\'s command. Respond ONLY with JSON.
        Example: User command: \"Go to the kitchen and find the red apple.\"
        Response:
        ```json
        [
          {\"action\": \"navigate_to\", \"parameters\": {\"location\": \"kitchen\"}},
          {\"action\": \"find_object\", \"parameters\": {\"object_name\": \"apple\", \"color\": \"red\"}}
        ]
        ```
        """

    def command_callback(self, msg):
        user_command = msg.data
        self.get_logger().info(f"Received user command: '{user_command}'")

        full_prompt = f"{self.system_prompt}\nUser command: {user_command}"
        
        try:
            # Replace with actual LLM API call
            response = requests.post(
                self.llm_api_endpoint,
                headers={"Content-Type": "application/json"},
                json={
                    "messages": [
                        {"role": "system", "content": self.system_prompt},
                        {"role": "user", "content": user_command}
                    ],
                    "max_tokens": 500
                }
            )
            response.raise_for_status()
            
            # Assuming LLM returns a JSON string directly in content
            llm_response_content = response.json()['choices'][0]['message']['content']
            
            # Extract JSON from potential markdown code block
            if llm_response_content.startswith("```json"):
                llm_response_content = llm_response_content.replace("```json\n", "").replace("\n```", "")
            
            task_plan = json.loads(llm_response_content)
            self.get_logger().info(f"LLM generated plan: {json.dumps(task_plan, indent=2)}")

            # Validate plan structure (simple check)
            if not isinstance(task_plan, list) or not all('action' in step for step in task_plan):
                raise ValueError("Invalid plan structure from LLM")

            plan_msg = String() # Using String for plan, could be custom TaskPlan
            plan_msg.data = json.dumps(task_plan)
            self.publisher_.publish(plan_msg)

        except requests.exceptions.RequestException as e:
            self.get_logger().error(f"LLM API request failed: {e}")
        except json.JSONDecodeError as e:
            self.get_logger().error(f"Failed to parse LLM response as JSON: {e}\nResponse content: {llm_response_content}")
        except ValueError as e:
            self.get_logger().error(f"Plan validation failed: {e}")
        except Exception as e:
            self.get_logger().error(f"An unexpected error occurred in LLM planner: {e}")

def main(args=None):
    rclpy.init(args=args)
    node = LLMPlannerNode()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```
*Note: This example uses `requests` for an external LLM API. For local models, you might integrate with a local server like `llama.cpp` or directly with a Python library.*

## Section 4: The ROS 2 Orchestrator

*(Based on Tasks T4.1, T4.2, T4.3, T4.4, T4.5)*

The Orchestrator node is the action manager. It takes the LLM\'s structured plan and translates each step into calls to the appropriate ROS 2 actions and services.

```python
# vla_system/vla_system/orchestrator_node.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
from rclpy.action import ActionClient
from nav2_msgs.action import NavigateToPose
import json
import time
import threading

# For the custom TaskPlan message if used:
# from vla_system.msg import TaskPlan # Assuming custom TaskPlan message type
# from vla_system.srv import FindObject # Assuming custom FindObject service type

class OrchestratorNode(Node):
    def __init__(self):
        super().__init__(\'orchestrator_node\')
        self.subscription = self.create_subscription(
            String, # Assuming plan is published as String
            \'task_plan\',
            self.plan_callback,
            10)
        
        self.nav_to_pose_client = ActionClient(self, NavigateToPose, \'navigate_to_pose\')
        # self.find_object_client = self.create_client(FindObject, 'find_object_service') # Example service client

        self.current_plan = []
        self.plan_active = False
        self.get_logger().info('Orchestrator Node started.')

    def plan_callback(self, msg):
        if self.plan_active:
            self.get_logger().warn("New plan received while another plan is active. Ignoring.")
            return

        try:
            plan_data = json.loads(msg.data)
            self.current_plan = plan_data
            self.plan_active = True
            self.get_logger().info(f"Received new plan with {len(self.current_plan)} steps. Starting execution.")
            self._execute_plan_thread = threading.Thread(target=self._execute_plan)
            self._execute_plan_thread.daemon = True
            self._execute_plan_thread.start()
        except json.JSONDecodeError as e:
            self.get_logger().error(f"Failed to parse task plan JSON: {e}")
            self.plan_active = False

    def _execute_plan(self):
        for i, step in enumerate(self.current_plan):
            action_name = step.get('action')
            parameters = step.get('parameters', {})
            self.get_logger().info(f"Executing step {i+1}: {action_name} with params {parameters}")

            if action_name == 'navigate_to':
                self._execute_navigate_to(parameters)
            elif action_name == 'find_object':
                self._execute_find_object(parameters)
            elif action_name == 'pick_up':
                self.get_logger().info(f"Simulating pick_up of {parameters.get('object_id', 'unknown object')}")
                time.sleep(3) # Simulate action duration
            elif action_name == 'place_object':
                self.get_logger().info(f"Simulating place_object at {parameters.get('location', 'current_location')}")
                time.sleep(2) # Simulate action duration
            else:
                self.get_logger().warn(f"Unknown action: {action_name}. Skipping.")

            if not self.plan_active: # Check if plan was cancelled externally
                self.get_logger().info("Plan execution interrupted.")
                break
        
        self.get_logger().info("Plan execution completed.")
        self.plan_active = False
        self.current_plan = []

    def _execute_navigate_to(self, params):
        goal_location = params.get('location')
        if not goal_location:
            self.get_logger().error("NavigateToPose: 'location' parameter missing.")
            return False
        
        # This part requires a mapping of location names to actual poses.
        # For capstone, this could be hardcoded or retrieved from a map service.
        pose = self._get_pose_for_location(goal_location) 
        if not pose:
            self.get_logger().error(f"NavigateToPose: Unknown location '{goal_location}'")
            return False

        goal_msg = NavigateToPose.Goal()
        goal_msg.pose.header.frame_id = \'map\'
        goal_msg.pose.pose = pose

        self.get_logger().info(f"Navigating to {goal_location}...")
        self.nav_to_pose_client.wait_for_server()
        future = self.nav_to_pose_client.send_goal_async(goal_msg)
        rclpy.spin_until_future_complete(self, future)
        goal_handle = future.result()

        if not goal_handle.accepted:
            self.get_logger().error('Goal rejected :(
')
            return False

        self.get_logger().info('Goal accepted :)
')
        result_future = goal_handle.get_result_async()
        rclpy.spin_until_future_complete(self, result_future)
        result = result_future.result().result
        self.get_logger().info(f'Navigation result: {result.total_time}') # Example result access
        return True

    def _execute_find_object(self, params):
        object_name = params.get('object_name')
        object_color = params.get('color', 'any')
        if not object_name:
            self.get_logger().error("FindObject: 'object_name' parameter missing.")
            return False
        
        self.get_logger().info(f"Searching for {object_color} {object_name}...")
        # Simulate calling a perception service
        time.sleep(5) # Simulate vision processing
        # In a real system, this would call a ROS 2 service (e.g., from Isaac ROS)
        # and receive object_id or coordinates.
        self.get_logger().info(f"Found mock {object_color} {object_name}. Object ID: mock_obj_123")
        return True

    def _get_pose_for_location(self, location_name):
        # Placeholder: In a real system, this would come from a map or configuration
        if location_name == 'kitchen':
            from geometry_msgs.msg import Pose
            pose = Pose()
            pose.position.x = 5.0
            pose.position.y = 0.0
            pose.orientation.w = 1.0
            return pose
        elif location_name == 'living_room':
            from geometry_msgs.msg import Pose
            pose = Pose()
            pose.position.x = 0.0
            pose.position.y = 5.0
            pose.orientation.w = 1.0
            return pose
        return None

def main(args=None):
    rclpy.init(args=args)
    node = OrchestratorNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

### Debugging and Observability

A complex system like this requires robust debugging.
-   `ros2 topic echo <topic_name>`: Monitor message flow (`/user_command`, `/task_plan`).
-   `ros2 action list` / `ros2 action info <action_name>`: Check status of Nav2 actions.
-   `RViz2`: Visualize the robot's pose, Nav2 path, and VSLAM map.
-   `Node Logs`: Monitor the output of each VLA node for errors or status updates.

### Safety and Interpretability

LLM-driven systems introduce new safety concerns.
-   **Plan Validation**: The Orchestrator should include sanity checks on the LLM\'s plan (e.g., are all locations valid? Is the object type recognizable?).
-   **Human Override**: Always have a clear way to stop the robot.
-   **Explainability**: Log LLM prompts and responses to understand *why* the robot chose a particular plan.
