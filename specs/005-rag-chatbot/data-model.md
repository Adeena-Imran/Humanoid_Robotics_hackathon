# Data Model: RAG Chatbot

This document defines the key entities and their attributes for the RAG Chatbot system.

## 1. Book Content (Conceptual)

*   **Description:** Represents the raw source material of the textbook.
*   **Purpose:** The foundation from which `Content Chunks` are derived.
*   **Attributes:**
    *   `file_path`: Path to the Markdown/MDX file (e.g., `intro-humanoid-robotics.mdx`).
    *   `raw_text`: The complete content of the Markdown/MDX file.

## 2. Content Chunks (Stored in Qdrant)

*   **Description:** Smaller, semantically coherent segments of book content derived from the `Book Content`. These are the units stored in the vector database for retrieval.
*   **Purpose:** To enable granular semantic search and retrieval relevant to user queries.
*   **Storage:** Qdrant Vector Database.
*   **Attributes:**
    *   `id`: Unique identifier for the chunk (e.g., hash of content + metadata, or UUID).
    *   `text` (string): The actual text content of the chunk.
    *   `embedding` (vector): The dense vector representation of the `text` for similarity search.
    *   `metadata` (object): Additional structured information about the chunk.
        *   `chunk_id` (string): A unique, stable identifier for the chunk, useful for debugging and referencing.
        *   `chapter_title` (string): The title of the chapter the chunk belongs to.
        *   `section_title` (string, optional): The title of the section/heading the chunk belongs to.
        *   `source_file` (string): The filename of the original Markdown/MDX file.
        *   `page_number` (integer, optional): The estimated page number within the original book content (if applicable).
        *   `start_char` (integer, optional): Starting character index of the chunk in the original file.
        *   `end_char` (integer, optional): Ending character index of the chunk in the original file.
        *   `content_hash` (string): Hash of the `text` content to detect changes.

## 3. Chapter Summaries (Stored in Neon Serverless Postgres)

*   **Description:** Pre-computed high-level summaries for each chapter to facilitate whole-book summarization and quick chapter overviews.
*   **Purpose:** To provide quick access to chapter summaries and as building blocks for the whole-book summary.
*   **Storage:** Neon Serverless Postgres.
*   **Attributes:**
    *   `chapter_id` (string): Unique identifier for the chapter (e.g., derived from chapter title).
    *   `chapter_title` (string): The title of the chapter.
    *   `summary_text` (string): The generated summary for the chapter.
    *   `last_updated` (timestamp): Timestamp of when the summary was last generated/updated.
    *   `source_file` (string): The primary source file associated with the chapter.

## 4. User Query (Ephemeral/Request Object)

*   **Description:** Represents the input provided by the user to the chatbot.
*   **Purpose:** To guide the RAG system in retrieving relevant information and generating a response.
*   **Attributes:**
    *   `text` (string): The user's natural language question or request.
    *   `query_type` (enum: 'explanation', 'chapter_summary', 'book_summary'): Categorization of the user's intent.
    *   `selected_text` (string, optional): The text snippet highlighted by the user for context-specific explanations.
    *   `chapter_id` (string, optional): The identifier for a specific chapter if a chapter summary is requested.

## 5. Chatbot Response (Ephemeral/Response Object)

*   **Description:** The output generated by the RAG system in response to a `User Query`.
*   **Purpose:** To deliver an answer or summary to the user.
*   **Attributes:**
    *   `response_text` (string): The generated answer or summary text.
    *   `sources` (array of objects): References to the `Content Chunks` or `Chapter Summaries` used to generate the response.
        *   `source_file` (string): The original filename of the source.
        *   `chapter_title` (string): The chapter title of the source.
        *   `section_title` (string, optional): The section title of the source.
        *   `chunk_id` (string, optional): The ID of the specific chunk used.
    *   `generated_at` (timestamp): Timestamp of when the response was generated.
    *   `model_id` (string): Identifier of the LLM used for generation.
